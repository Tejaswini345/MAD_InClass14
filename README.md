# Cloud Courier: Firebase Cloud Messaging in Flutter

CSC 4360 Mobile App Development, In-Class Activity 14

Cloud Courier is a Flutter app that receives Firebase Cloud Messaging (FCM) messages and uses custom data keys to change what is shown on screen. It handles messages in the foreground, from the background, and from a terminated state, and it rejects invalid payloads without crashing.

## How it works

A message sent from the Firebase Console carries two custom string data keys:

| Key | Allowed values | Effect |
|---|---|---|
| `action` | `update_ui` | Tells the app to apply the message |
| `asset` | `default`, `promo` | Selects a bundled image (teal or orange) |

If `action` is wrong, `asset` is missing, or `asset` is not in the allow-list, the app keeps the previous title and image, shows a red diagnostic card, and does not crash.

Sample payload:

```json
{
  "notification": { "title": "New promotion", "body": "Switch the screen to the promo asset" },
  "data": { "asset": "promo", "action": "update_ui" }
}
```

## Project structure

```
lib/
  main.dart            Firebase init, top-level background handler, app entry
  fcm_service.dart     FCMService: permission, token, all listeners, payload validation
  home_page.dart       UI: title, image, handler/receipt/message ID card, token
  firebase_options.dart  Generated by flutterfire configure
assets/images/         default.png, promo.png
```

## Message handlers

| App state | Handler | Where |
|---|---|---|
| Foreground | `FirebaseMessaging.onMessage` | `FCMService` |
| Background, user taps notification | `FirebaseMessaging.onMessageOpenedApp` | `FCMService` |
| Terminated, user taps notification | `FirebaseMessaging.instance.getInitialMessage()` | `FCMService` |
| Background processing | `FirebaseMessaging.onBackgroundMessage` | Top-level function in `main.dart` |

The background handler runs in a separate isolate, so it cannot touch widget state. It only logs. `FCMService` owns every listener, guards against double initialization, and cancels its subscriptions on dispose.

## Setup

Prerequisites: Flutter SDK, Firebase CLI (`npm i -g firebase-tools`), FlutterFire CLI (`dart pub global activate flutterfire_cli`), and an Android emulator with Google Play services.

```bash
flutter pub get
firebase login
flutterfire configure --platforms=android
```

`flutterfire configure` generates `lib/firebase_options.dart` and `android/app/google-services.json` for your own Firebase project.

Make sure `android/app/src/main/AndroidManifest.xml` contains, above `<application>`:

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
```

If the build complains about `minSdk`, set it to 23 in `android/app/build.gradle.kts`.

Versions used: `firebase_core` 4.15.2 and `firebase_messaging` 16.7.1. Do not upgrade to the 17.x line, which uses a different registration flow.

## Run

```bash
flutter run
```

Allow notifications when prompted. The token appears on screen; use **Copy token**, or copy it from the `[FCM token]` line in the terminal. The emulator needs internet access (turn airplane mode off).

## Test

In the Firebase Console, open Messaging, create a Notification message, add custom data `asset=promo` and `action=update_ui`, then use **Send test message** with your token.

| Test | Steps | Expected "Last handler" |
|---|---|---|
| T1 Foreground | App open, send | `onMessage`, image turns orange |
| T2 Background tap | Press Home, send, tap the notification | `onMessageOpenedApp` |
| T3 Cold-start tap | Swipe app away from recents (not Force stop), send, tap the notification | `getInitialMessage` |
| T4 Invalid payload | App open, send with `asset` missing or `unknown` | `onMessage`, red diagnostic, UI unchanged |

The screen shows the last handler, a receipt count for this launch, and the message ID, so each test can be shown as a fresh event even when the same payload is reused.

| Test | Result |

## Design notes

- **Allow-list validation:** `asset` values are checked against a fixed map of bundled images, so untrusted data can never build an invalid asset path.
- **Delivery is not authorization:** a delivered message is not assumed to be trustworthy, so it is validated before it changes the UI.
- **Single listener owner:** `FCMService` registers listeners once, which avoids duplicate handling.

## Limitations

- Tested on one Android emulator with one payload shape. Results do not cover iOS, real-device battery policies, or data-only background messages.
- Android Force stop prevents delivery until the app is reopened.
- FCM delivery is not guaranteed and should not be the only channel for safety-critical messages.
- Repeated sends are processed again. A future improvement is an application-level event ID so duplicates are ignored.

## Security

Do not commit real FCM tokens or share them publicly.
